# 訓練家隊伍固定 UI 辨識：人工驗收紀錄

## 目的與隱私邊界

本紀錄用於以真實的 Pokémon GO 訓練家個人檔案截圖，確認隊伍僅由固定 UI 證據判定，而非 Buddy 寶可夢、暗影特效或整體畫面顏色判定。

- 私人截圖、原始 API 回應、資料 URL 與任何帳號憑證均不得提交至版本庫或貼入此文件。
- 自動化測試只使用 mocked structured responses，不會發出付費或即時 OpenAI 請求。
- 下表每一列必須由操作人員在所記錄的確切 commit SHA 上實際執行後，才可標示為「通過」；mocked fixture 的結果不可取代真實影像人工驗收。
- 每次實際執行前都必須以 `git rev-parse HEAD` 記錄當次測試的完整 SHA；不可填分支名稱，也不可沿用先前執行的 SHA。

## 執行方式

1. 在隔離測試帳號或本機開發環境載入一張真實截圖；不要上傳或保存截圖副本到版本庫。
2. 開啟瀏覽器開發者工具，確認 `window.lastTrainerTeamDiagnostics` 只含安全診斷資料，且沒有 API key、Authorization、資料 URL、File 物件或憑證。
3. 記錄「原始固定 UI 證據」：等級大數字、XP 填滿段、XP 數字文字，以及可見時的名稱區塊與箭頭／加號／進度裝飾；不要將 Buddy、暗影煙霧或背景色記為證據。
4. 比對有效隊伍、表單 `g_team` 實際值與預期值；若不符，填寫失敗原因並保留截圖於授權的私有位置。

## 人工驗收判定

- 固定 UI 證據通過驗證時，狀態應為「隊伍辨識完成：黃隊／藍隊／紅隊」，且表單值相同。
- 固定 UI 證據不足或相互衝突時，狀態應為「隊伍需人工確認：…」；不得把預設或既有隊伍值描述成這次 AI 辨識成功。
- Buddy 本體顏色、寶可夢種類、暗影 aura／紫煙、人物服裝、整體主色、中央背景與底部綠色按鈕都不是可接受的隊伍證據。
- 若本輪不確定，使用者手動選擇的隊伍不得被覆寫；較舊、延遲的掃描也不得覆寫較新的掃描結果。
